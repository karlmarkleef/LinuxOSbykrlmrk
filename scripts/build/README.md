# Build scripts

All scripts operate on project inputs under H: and use the Arch bootstrap root inside a Linux-capable WSL2 environment. They do not install software into Windows or Debian.

- `verify-arch-bootstrap.ps1` downloads and verifies the pinned official bootstrap archive and signature.
- `extract-arch-bootstrap.sh` extracts that verified input into `/var/tmp/marklinux-bootstrap/root.x86_64` and refuses to replace an existing root.
- `prepare-arch-tools.sh` installs the pinned tool names from `tools/build/bootstrap-packages.txt` inside that disposable Arch root.
- `clone-wsl-build-distro.ps1` makes a byte-verified copy of an existing WSL VHDX under the project on H: and registers that copy under a separate distribution name. It does not unregister or alter the source. It was used with approval to create `MarkLinuxBuildTools`; the original `Debian-Recovered` remains registered and unchanged.
- `build-base-iso.sh` builds the BIOS/UEFI live ISO for the selected profile. It checks for at least 4 GiB free for the base profile and 12 GiB for the desktop profile before extraction. The ISO and logs are written under `builds/`; task-owned temporary work is removed after clean unmount unless `MARKLINUX_KEEP_WORK=1` is set for debugging. It refuses to overwrite the expected ISO.
- `verify-base-iso.sh` inspects an ISO anywhere inside the project and boots it under QEMU TCG with a CD-ROM only, sends Enter to select the default boot entry, then saves a VGA screenshot and log. Defaults are 4 vCPU, 4 GiB RAM, a 5-second key delay, and a 140-second capture delay; `MARKLINUX_QEMU_CPUS`, `MARKLINUX_QEMU_MEMORY_MB`, `MARKLINUX_QEMU_BOOT_KEY_DELAY_SECONDS` (1-300s), and `MARKLINUX_QEMU_WAIT_SECONDS` can adjust them within guarded limits. Optional `MARKLINUX_QEMU_POST_BOOT_ACTION=hardware-summary` attempts to press Enter on the first Welcome action, then captures a screenshot after `MARKLINUX_QEMU_POST_BOOT_WAIT_SECONDS` (1-60s); inspect the image to determine whether the guest accepted the key. It does not pass any host disk to QEMU.
- `verify-desktop-kernel.sh` extracts the kernel/initramfs from the ISO and boots those files directly while retaining the ISO as a read-only live medium. It captures both VGA and serial output; this bypasses the ISO boot menu, so use it to diagnose the live OS and use `verify-base-iso.sh` for boot-menu/bootloader coverage.
- `build-hardware-detect.sh` checks Rust formatting, runs fixture-based tests on Linux, builds the release x86_64 Linux CLI in the isolated Arch root, and saves the binary and checksum under `builds/artifacts/`. `rust` is in `tools/build/bootstrap-packages.txt`; it is installed only inside that Arch root.
- `build-mcp-windows.sh` builds the Mark Compatibility Platform Windows runtime tools (`mark-runtime`, `mark-pe-inspect`, `mark-apk-inspect`) from `windows/` and `android/apk-installer/`, stages the release binaries and the Android manager/APK scripts into the desktop ISO source overlay, and invokes the desktop ISO build. Staged binaries are removed on exit.

Invoke Linux scripts from PowerShell with `wsl -d MarkLinuxBuildTools -u root -- bash /mnt/h/LinuxOSbykrlmrk/scripts/build/<script-name>`. The clone's ext4 VHDX is under `tools/wsl-build/` on H:. C: remains critically low, so WSL warns that it cannot create its default swap VHDX there. The clone still starts and builds; neither C: nor `.wslconfig` has been modified. The original C:-hosted distro has not been started or changed since the storage failure.
